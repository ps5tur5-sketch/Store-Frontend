# Game Goods Frontend

Самостоятельная Vue 3/Vite витрина магазина цифровых товаров. Production image
собирается Vite и раздаётся Nginx. Backend в этот контейнер не встроен: адрес API
полностью задаётся через `.env` и runtime `config.js`.

Парный backend с PostgreSQL:
<https://github.com/ps5tur5-sketch/Store-Backend>.

## Быстрый запуск

Сначала должен работать Game Goods Backend. Для frontend нужен только Docker с
Compose plugin:

```bash
docker compose up -d --build
```

Открыть:

- витрина: <http://127.0.0.1:8080/>;
- регистрация и покупки: <http://127.0.0.1:8080/account>;
- корзина: <http://127.0.0.1:8080/cart>;
- скрытая админка: <http://127.0.0.1:8080/admin>.

Проверка и логи:

```bash
docker compose ps
curl -I http://127.0.0.1:8080/
docker compose logs -f frontend
```

Остановка:

```bash
docker compose down
```

## Подключение к backend без правки кода

Все сетевые адреса задаются в `.env`:

```dotenv
API_BASE_URL=http://127.0.0.1:3000
FRONTEND_BIND_IP=0.0.0.0
FRONTEND_PORT=8080
```

Для backend на другом сервере:

```dotenv
API_BASE_URL=http://203.0.113.10:3000
FRONTEND_BIND_IP=0.0.0.0
FRONTEND_PORT=8080
```

После изменения адреса пересобирать image не нужно — Nginx entrypoint создаёт
`config.js` при каждом старте контейнера:

```bash
docker compose up -d
```

Если страница frontend открыта по HTTPS, а `API_BASE_URL` начинается с HTTP,
браузер заблокирует запросы как Mixed Content. Для внешнего стенда публикуйте оба
проекта по HTTPS либо оба по HTTP. Backend тестового задания разрешает CORS с
любого origin.

## Пользовательские маршруты

| Маршрут | Назначение |
|---|---|
| `/` | каталог, поиск, категории, сервисные блоки и отзывы |
| `/product/:sku` | полная карточка, описание, характеристики, добавление в корзину |
| `/cart` | количество, удаление, ручной код, расчёт и checkout |
| `/account` | регистрация/login, баланс, история покупок по дате |
| `/purchase/:id` | отдельная страница купленного товара |
| `/admin` | склад, платёжные коды, поставщики, ledger и recovery |

На публичной странице нет ссылки или вкладки admin. `/admin` открывается только
прямым URL и намеренно не защищён — это требование переносимого тестового стенда,
не production-практика.

## Полный пользовательский сценарий

1. Зарегистрироваться по логину и паролю — email не нужен.
2. Получить стартовый баланс 5000 баллов.
3. Открыть карточку товара и добавить его в корзину.
4. В корзине изменить количество или удалить позиции.
5. Оставить поле кода пустым для оплаты всей суммы баллами либо вручную ввести
   конкретный одноразовый код из базы.
6. Интерфейс запрашивает backend quote и показывает номинал, вычет кода, сумму с
   баланса и баланс после покупки.
7. После checkout popup показывает каждую купленную карточку и случайно выданный
   товарный ключ. Стрелки позволяют пройти все товары заказа.
8. Каждая покупка остаётся в истории, отсортированной от новой к старой, и снова
   открывается кликом.

### Частичная оплата кодом

Frontend не придумывает стоимость кода. После ручного ввода он вызывает
`POST /api/cart/quote` и отображает серверный расчёт:

```text
стоимость заказа       10 739
номинал кода             5 000
вычитает код            -5 000
к списанию с баланса     5 739
баланс пользователя      5 000
не хватает                 739
```

В этом случае кнопка disabled, а код не расходуется. Для заказа `7500` и кода
`5000` интерфейс покажет `Код + 2 500 баллов с баланса`; после покупки баланс
станет `2500`. Неизвестные и уже использованные коды явно отклоняются.

Checkout всё равно пересчитывается backend внутри транзакции: данные интерфейса
являются предпросмотром, а не доверенной платёжной логикой.

## Админка `/admin`

Админ-интерфейс позволяет:

- выбрать SKU и поставщика A/B;
- добавить один или пачку складских ключей; каждый автоматически становится
  платёжным кодом с номиналом цены выбранного SKU;
- увидеть доступные и выданные ключи;
- добавить пачку одноразовых платёжных кодов и задать номинал каждого;
- увидеть статус, номинал, пользователя и дату погашения кода;
- настроить normal, always-fail, out-of-stock, timeout-before-issue и
  timeout-after-issue для каждого поставщика;
- посмотреть summary, double-entry ledger и reconciliation;
- запустить worker/recovery вручную.

Начальное значение формы платёжного кода — 5000 баллов, но администратор может
ввести любой положительный номинал до 10 000 000.

## Внешний вид и иконки

Композиция главной повторяет предоставленный референс: узкая белая витрина,
header, поиск, чёрный промо-слайдер, сервисные плитки, категории, товарные ряды,
отзывы и footer. Изображения референса хранятся локально в `public/assets`.

Иконки не заменены буквами или emoji:

- Iconify используется для настоящих брендовых SVG-логотипов;
- Lucide Vue используется для интерфейсных SVG-иконок;
- CDN и внешняя загрузка иконок не требуются.

## Разработка без Docker

Требуется Node.js 22+.

```bash
npm ci
npm run dev
```

Vite будет доступен на <http://127.0.0.1:5173>. Dev proxy берёт backend из
`VITE_DEV_API_TARGET` в `.env`.

Проверки и production build:

```bash
npm run typecheck
npm run build
npm run preview
```

Docker production frontend работает на `8080`, а не на Vite-порту `5173`.

## Диагностика

Пустая страница:

```bash
docker compose ps
docker compose logs frontend
curl -I http://127.0.0.1:8080/
```

Ошибка API/CORS:

```bash
curl http://BACKEND_IP:3000/health
docker compose exec frontend cat /usr/share/nginx/html/config.js
```

Убедитесь, что адрес написан `localhost`, а не `localost`, и что открывается
Docker-порт `8080`. Порт `5173` используется только командой `npm run dev`.
